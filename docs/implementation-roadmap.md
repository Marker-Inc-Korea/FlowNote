# FlowNote 구현 로드맵

이 문서는 2026-07-14 현재 코드에서 완료된 범위와, 아직 구현되지 않은 예외 작업을 분리한다. “완료된 기반”은 코드가 존재하는 항목이며 운영 실기 통과를 뜻하지 않는다.

## 설계 완료, 부분 구현

- 외부 AI 1단계의 범위, 데이터 모델, API, 보안·보존 계약을 정리하고 질의 생성·조회 라우터, ORM 테이블, 기능 플래그·전송 승인, 원천 권한·민감정보 필터, 최소 payload provider 주입 경계와 인용 검증을 구현했다. 허용 범위는 근거 검색과 요약이며, 운영 provider client와 네트워크 호출은 아직 구현하지 않았다.
- 현재 동작하는 AI 기능은 `ai_search_candidates` 재생성·목록·품질 API, 오프라인 ground-truth 회귀 평가와 결과 누적, WPF 운영 점검 화면, 외부 질의의 비활성 기본값·승인·목적·원천 권한·민감정보·최소 payload·근거 snapshot·감사 게이트다. 운영 provider client와 네트워크 호출은 완료된 코드로 간주하지 않는다.

## 개발 우선순위 원칙

- 현재 단계에서는 핵심 기능과 현장 데이터 축적 흐름을 구현하고 안정화하는 일을 우선한다.
- UX 세부 조정과 고도화는 사전 가정만으로 확정하지 않고, 실제 현장의 작업 방식, 단말기 위치, 입력 가능한 순간과 사용자 피드백을 확인하면서 단계적으로 반영한다.
- 다만 권한, 보안, 데이터 손실 방지, 오류 복구와 기능 사용에 필요한 기본 안내는 UX 후속 개선으로 미루지 않고 기능 완료 기준에 포함한다.

### 현장 방문에서 확인한 근거

현장 방문 과정에서 FlowNote는 기능적인 측면에서는 이미 많은 부분이 개발되어 있으며, 현재 구현된 기능만으로도 실제 업무에 적용해 사용할 수 있는 수준이라는 의견을 확인했다. 문서 관리, 현장 기록, 알림과 인수인계처럼 제품의 중심이 되는 기능의 방향과 필요성 자체는 현장에서도 긍정적으로 받아들여졌고, 기능이 전혀 부족해서 사용할 수 없다는 평가보다는 이미 갖추어진 기능을 현장 업무에 어떻게 자연스럽게 연결할 것인지가 다음 과제로 제시되었다.

반면 화면 구성, 정보가 표시되는 순서, 버튼과 입력 방식, 용어와 안내 문구, 작업 흐름에 따른 이동 방법 등 UX 측면에서는 각 현장이 익숙하게 사용하는 방식과 요구에 맞춰 더 많이 개선해 주기를 바란다는 의견이 있었다. 여기서 말하는 개선은 단순히 화면을 보기 좋게 꾸미는 작업만을 뜻하지 않는다. 실제 작업자가 어느 위치에서 단말기를 사용하는지, 작업 중 언제 입력할 수 있는지, 어떤 정보를 먼저 확인하는지, 관리자와 현장 작업자가 같은 기능을 서로 어떻게 다르게 사용하는지까지 확인하여 불필요한 단계와 입력 부담을 줄이는 작업을 포함한다.

이 피드백을 근거로 현재 개발 계획은 핵심 기능과 데이터 축적 구조를 먼저 충분히 구현하고 안정화하는 방향을 유지한다. 동시에 UX를 완성된 것으로 간주하거나 뒤로 무기한 미루지 않고, 기능이 현장에서 실제로 사용되는 과정에서 나온 관찰과 요청을 수집해 우선순위를 정한다. 즉, 공통으로 필요한 기능은 제품 기반으로 먼저 확보하고, 현장별 선호와 업무 방식에 영향을 받는 UX는 실제 사용 맥락을 확인한 뒤 반복적으로 다듬는다. 이를 통해 사전 추측에 따른 과도한 화면 개발을 줄이면서도, 최종적으로는 현장 사용자가 자신의 업무 방식에 맞는 제품이라고 느낄 수 있도록 개선한다.

2. 현장별 MSI 설치 검증, 코드 서명, self-contained 패키징 조건 정리
3. Android 운영 배포 서명, MDM/인증서, 단말 등록/비활성화 절차 확정
4. Android 백그라운드 알림 정책과 Windows/Android 채널 polling 운영 UX 검증. WPF 서버 scope·사용자별 cursor 영구 보존, 전경 polling과 읽음/수신 확인은 구현되어 있다.
5. 구현된 사용자/역할 UI와 서버 계정 보호 규칙의 현장 운영 검증 및 오류 UX 보강
6. 문서 버전/상태/공개 상태의 서버-WPF 동기화 정책 고도화
7. FieldComment 관리자 검토/분석/선정 운영 화면 보강
8. AI 근거 후보 운영 점검과 ground-truth 회귀 평가를 실제 축적 데이터 기준으로 반복 검증
9. 현장 익명 샘플 기준에 맞춘 미리보기 예외 케이스 보강

## 후속 단계

- PostgreSQL 전환 조건 검토
- MES/ERP 어댑터 설계. 착수 전에는 수동 작업지시의 `work_order_no`, 문서 연결, 작업순서, FieldComment, 보고서 근거가 안정적으로 축적되어야 한다.
- 외부 AI 호출 기반 검색/작업 조언. 착수 기준은 [MVP 범위 문서의 후속 계층 착수 기준](./mvp-scope.md#후속-계층-착수-기준)을 따른다.
  - 원천별 사용자 열람 권한, 민감정보/전송 금지 필터와 최소 텍스트 payload는 구현됐다. 운영 호출 전 남은 항목은 summary-claim 의미 일치 검증, 운영 승인 API/UI와 provider client다.
  - 전송 승인·프롬프트 운영 API/UI, 질의 조회 범위, 만료 삭제·감사 스케줄러를 구현한다.
- 운영 감사 로그와 보안 정책 고도화

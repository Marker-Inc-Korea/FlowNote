# FlowNote 현장 소리 기록-260723

## 1\. 현장 사용성과 기본 방향

윈도우 앱은 기능이 많고 유용하지만, 사용해 보기도 전에 복잡하게 느껴집니다. 현장에서는 도면을 많이 보지만 해당 기능을 자주 사용하지 않으며, 도면 자체에 대한 필요성도 크지 않습니다.

현장에서는 엑셀 형태가 가장 편하기 때문에, 자료를 좀 더 쉽게 관리할 수 있는 엑셀 기반 방식이 필요합니다. 엑셀만큼 완벽할 필요는 없지만 배경색 등의 기능은 있으면 좋겠습니다.

다음 작업조에 인수인계할 때는 이 엑셀을 바로 넘기고, 이후 카톡이나 별도로 전달할 내용이 있으면 간단히 전달합니다.

## 2\. 사진 기록 방식

사진은 다음과 같은 경우에 남깁니다.

* 엑셀만으로 남길 수 없는 자료가 있을 때
* 보고용이 아니라 주의 사항을 전달해야 할 때
* 조금 더 신경 써야 하는 일이 있을 때

평소에는 사진을 상세히 남기지 않기 때문에 엑셀이 기본이 되어야 합니다.

## 3\. 안드로이드 앱과 설치 문제

안드로이드 앱 설치는 조금 더 고민해 보겠습니다. APK 파일을 설치하는 방식이 어렵기도 하고, 굳이 설치해야 하는지는 아직 확실하지 않습니다.

앱이 만들어지는 방향 자체는 있으면 좋겠지만, 아직 현장에 필요한지 체감되지 않아 앱의 필요성을 더 생각해 보겠습니다.

현장 맞춤형 기능까지는 아니더라도, 현장에 필요한 기능이 있다면 최대한 요구 사항에 맞춰줄 수 있는지에 대한 의견이 나왔습니다.

설치 방법도 좀 더 쉬워야 합니다. 현장에 외국인도 있는데, APK 설치를 위해 각자의 휴대폰을 열어 직접 설치해 주는 것은 요즘 문제가 될 수 있어 어렵습니다. 별도의 교육시간을 할애하기에는 할 일이 너무 많고, 휴대폰 종류도 모두 달라서 대응하기가 힘듭니다.

## 4\. 전달 사항의 전파와 확인 기록

전달할 사항은 바로 전파되었으면 합니다. 단순히 전파하는 것에 그치지 않고, 사용자가 확인했다는 사실이 정확히 기록되어야 합니다.

이를 다시 정리해 보고해야 하는 입장에서도 관련 내용이 잘 정리되었으면 합니다.

## 5\. 윈도우 터치패널 UX

현장에서 사용하는 윈도우 터치패널도 좀 더 간단한 형태로 제공되었으면 합니다. 윈도우 바탕화면처럼 아이콘을 쉽게 클릭해 들어가는 방식을 구현할 수 있는지 타진해 왔으며, 이에 대해서는 조금 더 생각해 보기로 했습니다.

바탕화면처럼 몇 개의 파일에 모든 것을 몰아넣는다면 굳이 새로 만들 이유가 없습니다. 다만 현재와 같은 탐색기 형태가 아니라, 필요한 기능이나 내용만 보여주는 방식은 구현할 이유가 있다고 판단합니다.

## 6\. 향후 개발 및 검증 방향

완성되어 가는 단계에서 방향을 급선회할 수는 없으므로 일부는 수용하되, 버릴 것은 버리는 방향으로 잠시 정리하는 시간이 필요할 것 같습니다.

UX는 공통적으로 다듬어야 하는 항목이 있으므로, 현재 현장 검증을 통해 계속 수정해 나가야 할 것 같습니다.

사용성이 다소 떨어지더라도 현장 사람의 시각과 개발자 또는 이론만으로 판단하는 방향은 다를 수 있습니다. 완벽하게 사용되지 않더라도 현장에 계속 선보이고 수정하는 방향으로 진행하겠습니다.

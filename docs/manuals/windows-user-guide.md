# FlowNote Windows 사용 매뉴얼

## 1. 적용 범위

이 문서는 2026-08-15 현재 Windows WPF 앱의 메뉴와 업무 절차를 설명한다. 앱은 승인된 운영 HTTPS 서버 계정으로 로그인하며, 로컬 SQLite는 업무 원천과 동기화 상태를 보존하는 용도다.

화면 배치는 이후 UX 개편으로 달라질 수 있다. 메뉴·버튼 이름과 업무 원칙이 다르면 현재 코드와 서버 권한 정책을 우선하고 이 문서를 함께 갱신한다.

## 2. 설치 전 확인

- Windows x64 PC
- 승인된 FlowNote MSI
- framework-dependent MSI 사용 시 .NET Windows Desktop Runtime 10 x64
- 문서 미리보기용 Microsoft Edge WebView2 Runtime
- 승인된 HTTPS 서버 주소와 서버 계정
- 운영 로컬 데이터 폴더 쓰기 권한

일반 운영 환경 변수는 다음 두 개다.

```powershell
setx FLOWNOTE_LOCAL_DATA_DIR "C:\FlowNote\LocalData" /M
setx FLOWNOTE_API_BASE_URL "https://<승인된 서버 DNS 이름>" /M
```

환경 변수 변경 뒤에는 앱과 기존 PowerShell을 닫고 새 세션에서 실행한다.

## 3. 로그인

1. FlowNote를 실행한다.
2. 로그인 화면의 `서버 로그인 대상`이 승인된 HTTPS 주소인지 확인한다.
3. 로그인 ID와 비밀번호를 입력한다.
4. 임시 비밀번호 계정이면 안내에 따라 비밀번호를 변경한다.
5. 변경 성공 뒤 새 비밀번호로 다시 로그인한다.

연결 실패, 인증서 오류, 401·403이 발생해도 로컬 계정이나 HTTP로 자동 전환하지 않는다. 화면에 표시된 보존 내용과 다음 조치를 확인하고 [장애 대응 매뉴얼](./troubleshooting.md)을 따른다.

## 4. 역할별 첫 업무

로그인 후 상단의 첫 업무 안내와 빠른 업무 버튼을 확인한다.

| 역할 | 권장 순서 |
| --- | --- |
| 관리자·문서 관리자·부서 관리자 | 코멘트 검토 → 보고서 근거 선정 → 동기화·충돌 확인 |
| 반장 | 인수인계 확인 → 문서 찾기·열람 → 작업판 |
| 조장 | 작업 전 문서 확인 → 인수인계 확인 → 채널 알림 |
| 조원·열람자 | 문서 찾기·열람 → 인수인계 확인 → 알림 확인 |

버튼이 비활성화되면 필요한 역할과 문의 방법이 도구 설명에 표시된다. 계정을 임의로 바꾸지 말고 현장 관리자에게 로그인 ID와 필요한 업무를 전달한다.

## 5. 메인 화면

### 5.1 문서 찾기

1. 왼쪽 `문서 구조`에서 폴더를 선택한다.
2. `검색`에 파일명, 제목 또는 관련 검색어를 입력한다.
3. 필요한 경우 `등록 태그`와 `상태`를 선택한다.
4. 문서 목록에서 파일명, 태그, 상태, 버전, 공개 버전과 수정 시각을 확인한다.
5. 문서를 두 번 누르거나 `선택 문서 열기`를 누른다.

현장 작업 전에는 단순히 가장 높은 버전 번호만 보지 말고 `공개` 버전을 확인한다.

### 5.2 상태 의미

| 상태 | 의미 |
| --- | --- |
| 작업중 | 작성·변경 중이며 현장 공개가 확정되지 않음 |
| 검토중 | 검토 절차 진행 중 |
| 공개 | 승인된 버전이 현장 공개본으로 지정됨 |
| 보관 | 현재 사용 대상에서 제외해 보존 |

## 6. 문서 등록

문서 등록 권한이 있는 역할만 수행할 수 있다. 운영 파일은 `문서 운영 > 파일 업로드` 또는 문서 목록의 Drag & Drop을 사용한다.

1. 문서를 둘 폴더를 선택한다.
2. 필요하면 `등록 태그`에 쉼표로 태그를 입력한다.
3. `문서 운영 > 파일 업로드`를 선택한다.
4. PDF, TXT, XLSX 또는 이미지 파일을 고른다.
5. 하단 상태에서 로컬 DB 저장과 서버 등록 결과를 확인한다.
6. 서버 등록 실패가 표시되면 같은 파일을 새 문서로 다시 올리지 않는다. 동기화 큐에 보존됐는지 먼저 확인한다.

등록된 문서는 자동 공개되지 않는다. 등록 뒤 검토 요청과 공개 절차를 진행한다.

`문서 등록` 메뉴는 현재 시각 기반의 예시 TXT 문서를 만드는 프로토타입 기능이다. 실제 운영 파일 등록에는 `파일 업로드`를 사용한다.

## 7. 문서 열람과 현장 코멘트

### 7.1 문서 열람

1. 문서 목록에서 문서를 연다.
2. `문서 내용`에서 미리보기를 확인한다.
3. 미리보기가 실패하면 문서 원본과 로컬 DB가 보존됐다는 안내를 확인한다.
4. 다운로드 권한이 있고 업무상 필요한 경우에만 `복사본 저장`을 사용한다.
5. 문서 창은 사용자가 직접 닫는다.

`복사본 저장`은 서버의 세션 바인딩 1회성 controlled copy와 SHA-256 검증을 사용한다. 저장한 복사본은 현장 보안 정책에 따라 관리한다.

### 7.2 FieldComment 작성

1. 문서 창 아래 `현장 코멘트`에 관찰한 사실을 입력한다.
2. 필요하면 `파일 첨부`로 사진이나 근거 파일을 선택한다.
3. 첨부 요약과 입력 내용을 다시 확인한다.
4. `저장`을 누른다.
5. 문서 창을 닫은 뒤 메인 화면 상태에서 저장 결과를 확인한다.

FieldComment에는 보고서 결론을 미리 쓰기보다 무엇을 봤고 어떤 문제가 있었는지 짧고 구체적으로 남긴다. 원문은 관리자 정리·분석 내용과 분리돼 보존된다.

## 8. 문서 검토와 공개

`문서 운영 > 검토·공개 승인 작업함`을 연다.

### 8.1 검토 요청

1. 새로 등록한 문서의 서버 문서 ID를 확인한다.
2. `새 검토 요청`에 문서와 요청 사유를 입력한다.
3. 검토 담당자와 기한을 지정한다.
4. `검토 요청`을 누른다.
5. version·revision·file hash가 고정됐는지 작업 목록에서 확인한다.

### 8.2 검토 담당자

1. `내 작업만`을 선택해 배정된 요청을 확인한다.
2. 요청 사유, 문서 ID, 버전 ID, 기한을 확인한다.
3. 실제 문서 내용과 변경 사유를 검토한다.
4. 사유를 입력하고 `승인` 또는 `반려`를 누른다.

### 8.3 공개 담당자

1. 승인된 요청과 정확한 버전을 확인한다.
2. `공개`를 누른다.
3. 메인 목록과 서버 공개 상태를 새로고침해 공개 버전을 확인한다.

잘못 공개한 경우 원본이나 이력을 삭제하지 않는다. 권한과 사유를 확인한 뒤 `승인 취소` 또는 새 버전의 재검토 절차로 정리한다.

## 9. FieldComment 검토

`현장 운영 > 코멘트 검토`를 연다.

1. 상단에서 미검토, 상충, 안전·품질 위험, 보고서 미연결, 담당자 없음과 기한 초과 수치를 확인한다.
2. 상태, 문서, 작성자, 태그, 기간, 신호등과 작업함 필터를 적용한다.
3. 우선 처리할 FieldComment를 선택한다.
4. `원천 기록(불변)`의 내용, hash, 첨부, 문서 버전과 채널 권한을 확인한다.
5. `관리자 정리 내용`과 `관리자 분석 내용`을 입력한다.
6. 담당자, 검토 기한과 상태 변경 사유를 입력한다.
7. `검토 내용 저장`을 누른다.
8. 상충 또는 위험 기록은 분석자와 결정자가 같은 사람인지 서버 정책을 확인한다.

여러 건을 처리할 때는 `선택 항목 일괄 저장` 전에 미리보기와 항목별 오류를 확인한다. 부분 성공 뒤에는 성공 항목을 다시 보내지 않고 실패 항목만 재선택한다.

## 10. 보고서 작성

`현장 운영 > 보고서`를 연다.

1. 보고서 제목과 관리자 요약을 입력한다.
2. `현장 코멘트 원천`, `관련 문서`, `작업순서 이력`에서 근거를 선택한다.
3. 서로 다른 원천 유형을 두 종류 이상 포함한다.
4. `초안 생성`을 누른다.
5. 선택 근거의 고정 버전과 검증 결과를 확인한다.
6. 근거가 바뀌었거나 서버 확인이 실패하면 저장하지 말고 원인을 해결한다.
7. `보고서 저장`을 누른다.
8. 필요하면 `검토중 전환`과 `고정 근거 확인`을 진행한다.

확정 보고서를 수정해야 할 때는 원본을 덮어쓰지 않는다. 보고서 상세의 정정 절차에서 독립 정정본을 만들고 다시 검토·승인한다.

## 11. 작업판과 작업순서 전달

`현장 운영 > 작업판`을 연다.

1. 날짜와 라인을 확인하고 `새 작업판`을 만든다.
2. 작업 항목 제목과 담당자를 입력해 `항목 추가`를 누른다.
3. 항목 순서는 `위로`, `아래로`로 조정한다. 변경 사유가 있으면 같은 입력란에 남긴다.
4. 상태를 `대기`, `진행중`, `보류`, `완료` 중에서 선택한다.
5. `보류`로 바꿀 때는 보류 사유를 반드시 입력한다. 다른 상태 변경도 감사에 남길 사유가 있으면 입력한다.
6. `알림 후보 전달`에서 현재 작업판 revision과 후보를 확인한다.
7. 대상 채널과 수신자를 확인한다.
8. 제목, 안내 문구와 전달 사유를 작성한다.
9. `채널로 전달` 또는 `인수인계 만들기`를 선택한다.
10. 성공·실패 수신자와 보존된 원천을 확인한다.

응답이 유실돼도 새 전달을 임의로 만들지 않는다. 기존 후보·채널 전달 receipt를 기준으로 실패 수신자만 다시 처리한다.

## 12. 채널과 인수인계

### 12.1 채널 관리

`알림 · 채널 > 채널 관리`에서 라인, 설비, 공정, 작업조 또는 인수인계 채널을 만든다. 멤버 역할은 소유자, 관리자, 멤버로 구분한다.

1. 채널 유형과 이름을 입력해 `채널 만들기`를 누른다.
2. 채널을 선택한다.
3. 사용자 ID와 채널 역할을 확인해 `멤버 추가`를 누른다.
4. 제외가 필요하면 사유와 영향을 확인한 뒤 `제외`를 누른다.

### 12.2 인수인계 확인 현황

`알림 · 채널 > 인수인계 확인 현황`에서 운영 단위·채널별 미확인과 후속 조치 인원을 확인한다.

- `읽음`: 내용을 열어본 상태
- `확인`: 업무를 인수한 상태
- `보류`: 즉시 인수하기 어렵고 확인이 필요한 상태
- `후속 필요`: 추가 FieldComment나 조치가 필요한 상태

후속 코멘트를 저장할 때 원천 인수인계 연결을 유지한다.

## 13. 계정과 승인 단말

`admin`, `system-admin`만 사용할 수 있다.

### 13.1 사용자 관리

1. `계정 · 단말 > 사용자 관리`를 연다.
2. `새 서버 계정`을 누른다.
3. 로그인 ID, 사용자 이름, 역할, 임시 비밀번호와 발급 사유를 입력한다.
4. `저장`을 누른다.
5. 사용자가 첫 로그인에서 비밀번호를 변경하고 재로그인했는지 확인한다.

잠금·비활성화, role 변경과 `비밀번호 재설정`은 기존 활성 세션을 폐기한다. `세션 강제 폐기`는 계정 탈취 의심, 역할 변경 반영 또는 운영 종료 때 사용하고 사유를 남긴다.

### 13.2 승인 단말 관리

1. `계정 · 단말 > 승인 단말 관리`를 연다.
2. Android 앱이 표시하는 정확한 `device_id`를 확인한다.
3. `신규 등록`에서 단말명, 위치, 그룹, 용도와 상태를 입력한다.
4. `등록`을 누른다.
5. Android 로그인이 성공하고 마지막 접속이 갱신되는지 확인한다.

분실·격리 단말은 `비활성`, 폐기 단말은 `폐기`로 변경한다. 교체 시 `교체 단말 준비`를 사용하면 선택한 기존 단말은 폐기 상태가 된다. 기존 Android outbox가 남아 있으면 승인된 보존·확인 절차를 먼저 수행한다.

## 14. 동기화와 충돌 확인

하단 상태와 `현장 운영 > 로컬 이력` 또는 `변경 이력`에서 다음을 확인한다.

- 전송 대기 건수
- 실패·충돌 건수
- 보류·폐기 건수
- 가장 오래 기다린 항목
- 최근 처리량과 오류 분포

실패 항목이 있다고 로컬 DB, `Files` 또는 큐를 삭제하지 않는다. 서버본 유지, 로컬 의도 재적용 또는 별도 관리자 판단 중 화면이 허용하는 종결 방법을 사용한다.

## 15. 종료 전 점검

- 작성 중인 입력을 저장했는지 확인한다.
- 문서 등록 뒤 서버 동기화 결과를 확인한다.
- 검토·보고서 작업의 상태 변경 사유를 남겼는지 확인한다.
- 전송 실패·충돌·보류 건수를 인계한다.
- controlled copy와 별도 저장 파일을 현장 보안 정책에 맞게 보관한다.
- 앱 창을 정상 종료한다.

# FlowNote Android 현장 사용 매뉴얼

## 1. 적용 범위

이 문서는 2026-08-15 현재 승인된 Android 태블릿·러기드 단말에서 공개 문서, 작업순서, FieldComment·사진, 알림과 인수인계를 사용하는 방법을 설명한다.

개인 휴대폰은 초기 배포 대상이 아니다. 운영 앱은 조직 소유 키로 서명하고 MDM 또는 승인된 사내 배포 절차로 설치한다. debug APK를 운영에 사용하지 않는다.

## 2. 사용 전 확인

- 관리자가 발급한 사용자 ID와 비밀번호
- Windows 관리 화면에 등록된 활성 `device_id`
- 승인된 운영 HTTPS 서버 주소
- 현장 Wi-Fi 또는 사내망 연결
- 사진 기록이 필요하면 카메라·파일 선택 권한
- 알림 사용이 필요하면 알림 권한과 MDM 절전 정책

단말을 재설치하거나 초기화하기 전에 전송 대기·실패 항목이 없는지 반드시 확인한다. 암호화 outbox는 다른 단말로 복사해 복호화할 수 없다.

## 3. 로그인

1. FlowNote 앱을 연다.
2. `서버 주소`가 승인된 HTTPS 주소인지 확인한다.
3. 관리자에게 전달받은 `승인 단말 ID`를 입력한다.
4. 사용자 ID와 비밀번호를 입력한다.
5. `로그인`을 누른다.
6. `로그인 완료`와 사용자 이름이 표시되는지 확인한다.

승인되지 않았거나 비활성·폐기된 단말은 로그인할 수 없다. 단말 ID를 임의로 바꾸지 말고 관리자에게 실제 표시값과 자산 정보를 전달한다.

## 4. 기본 화면

로그인 뒤 다음 주요 기능을 사용한다.

- `공개 문서`
- `알림`
- `인수인계`
- `오늘의 작업순서`
- 현장 기록 입력과 `사진 선택·확인`
- `기기에 저장·전송`
- `실패 항목 다시 보내기`

화면의 전송 상태에는 완료, 부분 성공, 전송 대기와 전송 실패 건수가 표시된다.

## 5. 공개 문서 열람

1. `공개 문서`를 누른다.
2. 열람 가능한 공개 문서 목록에서 문서를 선택한다.
3. 제목, 상태, 설명과 공개 버전을 확인한다.
4. `본문 보안 열람`을 누른다.
5. PDF는 `이전`, `다음`으로 페이지를 이동한다.
6. 열람이 끝나면 `열람 종료`를 누른다.

보안 뷰어는 다음 원칙으로 동작한다.

- 현재 공개 상태와 권한을 서버에서 다시 확인한다.
- 짧은 유효시간의 1회성 grant를 사용한다.
- 수신 크기와 SHA-256을 확인한다.
- 외부 열기, 공유와 최근 앱 노출을 제공하지 않는다.
- 화면 캡처를 차단한다.
- 열람 종료·오류·로그아웃 뒤 임시 파일을 정리한다.

문서가 비공개로 바뀌었거나 공개 버전이 없으면 열람하지 말고 관리자에게 공개 상태를 문의한다.

## 6. 오늘의 작업순서

1. `오늘의 작업순서`를 누른다.
2. `작업 날짜`가 오늘인지 확인한다.
3. 필요한 경우 `라인 코드`를 입력한다.
4. 보관 작업을 확인할 때만 `보관 작업판 보기`를 선택한다.
5. `작업판 새로고침`을 누른다.
6. 작업판의 제목, 라인, 항목 수와 revision을 확인한다.
7. 작업판을 선택해 항목 순서, 상태, 설명, 보류 사유와 연결 문서를 확인한다.

Android에서는 작업 항목 상태와 순서를 변경하지 않는다. 변경이 필요하면 Windows 관리자에게 요청한다.

연결이 끊긴 상태에서 최근 snapshot을 열면 `오프라인 읽기`와 마지막 저장 시각이 표시된다. 오프라인 snapshot이 현재 작업 변경을 반영한다고 가정하지 말고 연결 복구 뒤 새로고침한다.

## 7. 작업순서에서 문서 열기

작업 항목에 공개 문서가 연결돼 있으면 `연결 공개 문서 보안 열람`이 표시된다.

1. 작업 항목과 연결 문서 제목을 확인한다.
2. `연결 공개 문서 보안 열람`을 누른다.
3. 서버가 현재 공개 버전과 권한을 다시 확인한 뒤 문서를 연다.
4. 열람 뒤 `열람 종료`를 누른다.

작업판에 보였더라도 문서가 이후 비공개가 되면 열 수 없다.

## 8. FieldComment와 사진 기록

### 8.1 작업순서에서 시작

공개 문서가 연결된 항목에서 `이 항목에서 FieldComment·사진 시작`을 누른다. 앱이 작업순서 항목 ID, 작업판 revision과 당시 공개 문서 버전을 입력에 고정한다.

### 8.2 직접 입력

1. 문서 ID와 필요하면 문서 버전 ID를 확인한다.
2. `현장 기록 내용`에 관찰한 사실을 짧게 입력한다.
3. 현장에서 정한 분류 기준에 따라 녹색, 황색 또는 적색 신호를 선택한다. 적색 기록은 서버의 안전·품질 위험 검토 대상이 된다.
4. 사진이 필요하면 `사진 선택·확인`을 누른다.
5. 사진 미리보기와 `사진 1장 선택됨` 안내를 확인한다.
6. `기기에 저장·전송`을 누른다.
7. `기기에 암호화해 저장했습니다` 안내를 확인한다.

저장 버튼을 누르면 네트워크 전송보다 먼저 단말 암호화 저장을 확인한다. 저장 성공 뒤 입력란과 사진이 비워진다.

### 8.3 부분 성공

서버에 FieldComment가 저장됐지만 사진 전송만 실패할 수 있다. 이때 앱은 서버 `comment_id`를 유지하고 사진만 재전송한다. 같은 코멘트를 새로 작성하지 않는다.

## 9. 알림

1. `알림`을 누른다.
2. 제목, 발생 시각과 연결된 원천을 확인한다.
3. 필요한 알림을 열어 업무를 확인한다.
4. 읽음 처리 결과를 확인한다.

앱은 전경 polling으로 새 알림을 복구한다. 단말 강제 중지 상태에서는 Android가 자동 재시작을 막을 수 있으므로 MDM kiosk 재실행 또는 사용자의 앱 재실행이 필요하다.

같은 알림이 화면에 한 번 더 보이더라도 새 업무 원천이 생겼다고 판단하지 않는다. message ID와 원천을 기준으로 확인한다.

## 10. 받은 인수인계

1. `인수인계`를 누른다.
2. 제목, 내용, 상태와 원천 종류를 확인한다.
3. 문서가 연결돼 있으면 `관련 공개 문서 바로 열기`로 정확한 공개 버전을 확인한다.
4. 업무를 인수했으면 `확인`을 누른다.
5. 즉시 처리하기 어렵거나 추가 확인이 필요하면 사유를 입력하고 `보류`를 누른다.
6. 현장 기록이 필요하면 내용을 입력하고 `같은 원천에 후속 FieldComment 저장`을 누른다.

확인·보류와 후속 FieldComment는 전송 전에 단말에 암호화해 보존된다. 서버 저장 뒤 알림만 실패하면 같은 FieldComment를 다시 만들지 않고 알림 단계만 재시도한다.

## 11. 인수인계 작성

### 11.1 작업순서에서 시작

작업 항목의 `이 항목에서 인수인계 시작`을 누른다. 작업순서 원천과 공개 문서 버전이 자동으로 고정된다.

### 11.2 직접 작성

1. `채널·수신자 새로 불러오기`를 누른다.
2. 업무 채널을 선택한다.
3. 활성 수신자를 선택한다.
4. 원천 종류를 작업순서, 문서, FieldComment 또는 작업내역 중에서 선택한다.
5. 원천 ID와 필요한 문서 버전 ID를 확인한다.
6. 제목과 다음 작업자가 확인할 짧은 내용을 입력한다.
7. `기기에 암호화 저장·전송`을 누른다.
8. 입력란이 비워지고 보존·전송 상태가 표시되는지 확인한다.

활성 채널이나 수신자가 없으면 임의의 사용자에게 개인 메신저로 보내 FlowNote 처리 완료로 간주하지 않는다. Windows 채널 관리자에게 멤버십을 요청한다.

## 12. 전송 대기와 실패

### 자동 전송

- 새 `전송 대기` 항목은 앱이 자동으로 전송한다.
- 실패 항목은 재시도 시각에 따라 최대 12회 자동 재시도한다.
- 로그인 만료나 연결 단절이 발생해도 outbox를 삭제하지 않는다.

### 수동 전송

`실패 항목 다시 보내기`는 `전송 실패` 상태만 선택한다. 아직 첫 전송을 기다리는 `전송 대기` 항목과 완료 항목은 보내지 않는다.

1. 승인 단말로 다시 로그인한다.
2. 연결 상태를 확인한다.
3. `실패 항목 다시 보내기`를 누른다.
4. 성공, 부분 성공, 실패와 남은 대기 건수를 확인한다.

버튼을 반복해서 눌러도 새 원천을 만들기보다 같은 멱등키로 이어서 처리하지만, 오류 원인을 확인하지 않은 반복 조작은 피한다.

## 13. 보안 저장소 오류

다음과 비슷한 안내가 나오면 입력과 전송을 중단한다.

> 보안 저장소 오류 · 입력을 저장하거나 전송하지 않습니다.

이때는 다음을 지킨다.

1. 앱을 삭제하거나 단말을 초기화하지 않는다.
2. 암호화 DB와 첨부 파일을 수동으로 복사·수정하지 않는다.
3. 단말 ID, 사용자 ID, 발생 시각과 화면 문구를 관리자에게 전달한다.
4. 관리자는 단말을 비활성화하고 서버에 이미 저장된 원천과 idempotency key를 확인한다.
5. 승인된 보존·폐기 결정 뒤 새 단말을 등록한다.

Keystore 키가 없거나 무효화되면 기존 암호문을 새 단말에서 복호화하지 않는다.

## 14. 로그아웃과 단말 인계

1. 전송 대기·부분 성공·실패 건수를 확인한다.
2. 미전송 항목이 있으면 다음 사용자와 관리자에게 알린다.
3. 보안 문서 뷰어를 닫는다.
4. `로그아웃`을 누른다.
5. 로그아웃 완료와 임시 파일 정리 안내를 확인한다.

로그아웃은 업무 outbox를 삭제하지 않는다. 사용자·서버·단말 scope가 다른 로그인에서는 이전 snapshot과 입력을 임의로 재사용하지 않는다.

## 15. 금지 행동

- 개인 휴대폰에 운영 앱을 임의 설치하지 않는다.
- 승인되지 않은 서버 주소나 HTTP 주소를 입력하지 않는다.
- 화면 캡처 차단을 우회하지 않는다.
- 앱 파일을 외부 공유 앱으로 열려고 하지 않는다.
- 전송 대기 항목이 있는 단말을 초기화·폐기하지 않는다.
- 같은 현장 사실을 오류 확인 없이 새 FieldComment로 반복 작성하지 않는다.
- 개인 메신저 전달을 FlowNote 인수인계 완료로 기록하지 않는다.

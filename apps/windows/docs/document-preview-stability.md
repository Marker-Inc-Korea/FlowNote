# 문서 미리보기 안정화 기준

이 문서는 WPF 문서 뷰어의 실제 현장 파일 유형별 미리보기 기준이다. 일반 뷰어의 저장·다운로드는 차단하고 열람 시작과 사용자의 수동 닫힘 로그를 공통 적용한다. 별도 권한이 있는 사용자의 파일 저장은 뷰어 원본 복사가 아니라 서버 controlled copy 흐름만 사용한다.

2026-08-06 현재 구현 대상은 TXT, PDF, XLSX, 이미지이며 CAD/HWP 고급 뷰어와 Android Office 렌더링은 구현 예외다.

## 공통 로그 기준

- 문서 창을 열면 `document_view_logs`에 열람 시작 row를 만들고 `activity_history`에 `document.view_started`를 기록한다.
- 사용자가 창을 닫으면 같은 열람 row에 `closed_at`, `close_reason = window_closed`를 기록하고 `activity_history`에 `document.view_closed`를 기록한다.
- Windows 뷰어는 시간 기반 자동 닫힘을 수행하지 않는다. 기존 `auto_closed` 값은 과거 로그와 서버 동기화 호환을 위해서만 읽을 수 있다.
- 다운로드 또는 WebView2 PDF 저장/외부 창 요청이 차단되면 `close_reason = download_blocked`인 별도 접근 로그와 `document.download_blocked` 이력을 남긴다.
- 미리보기 실패, 안전 한도 초과, CAD/HWP 고급 뷰어 제외는 앱을 종료하지 않고 구조화된 한글 안내를 표시한 뒤 처리를 끝낸다. 안내에는 파일 유형, 실패 범주, 원본·문서 버전·열람 이력·앱 세션 보존 여부와 가능한 다음 행동을 표시한다.
- 실패 안내에는 기술 예외 원문, 스택 추적, 고객 식별정보와 로컬 절대경로를 표시하지 않는다. 감사에는 정해진 실패 코드만 기록한다.
- `view_started`, `view_closed`, `preview_failed`, `download_blocked`는 서버 `document_access_logs`와 공통 `audit_event_envelopes`에 같은 사용자·세션·장비·문서·버전·correlation ID 문맥으로 연결한다. 서버 연결이 없으면 기존 재시도 큐와 로컬 이력을 보존한다.
- controlled copy는 서버에 매핑된 현재 공개 버전에서만 활성화한다. 서버가 발급한 짧은 만료의 1회성 티켓으로 저장한 뒤 응답 SHA-256과 로컬 저장 파일을 다시 대조하며, 이 흐름은 `server_sync_queue`에 넣지 않는다.

## 현장형 익명 예외 샘플

기본 자동 검증은 다음 합성 익명 파일만 사용한다. 실제 익명 현장 표본은 고객·현장 책임자의 사용 승인, 승인된 실행 환경, 원본 반출 금지와 결과 보존 위치가 확인된 경우에만 별도 실행한다. 결과에는 `SYNTHETIC` 또는 `APPROVED_ANONYMOUS_FIELD` 출처를 반드시 기록하며 두 출처의 성공률, 실패 수와 판정을 합산하지 않는다. 저장소에는 실제 표본과 합성 바이너리 샘플을 추가하지 않는다.

## PDF/WebView2 보안 기준

- WebView2 PDF는 저장, 다른 이름 저장, 인쇄 도구를 숨긴다.
- 기본 컨텍스트 메뉴와 브라우저 단축키를 끈다.
- `DownloadStarting`은 항상 취소하고 다운로드 차단 이력을 남긴다.
- `NewWindowRequested`는 외부 창을 열지 않고 다운로드 차단 이력을 남긴다.
- 현재 PDF 원본 이외의 WebView2 이동을 취소해 웹 주소나 외부 앱으로 이어지지 않게 한다.
- WebView2 렌더러 프로세스가 실패하면 창과 앱 세션을 유지하고 구조화된 뷰어 실패 안내로 전환한다.
- PDF가 손상된 경우 WebView2로 이동하지 않고 한글 오류 안내와 실패 이력을 남긴다.

## 실패 안내 문구 기준

- 공통 필드: `파일 유형`, `실패 범주`, `보존 상태`, `가능한 다음 행동`을 항상 표시한다.
- 보존 상태: 원본 파일, 문서 버전, 열람 이력과 앱 세션이 유지됨을 표시한다.
- 다음 행동: 원본 위치, 권한, 정상 승인본, 지원 형식 변환 또는 WebView2 Runtime 중 실패 범주에 맞는 담당자 조치를 안내한다.
- 금지 정보: 예외 형식·메시지·스택 추적, 고객/현장 식별값, 로컬 절대경로, 서버 오류 본문을 표시하지 않는다.

## CAD/HWP 제외 범위

CAD와 HWP 고급 뷰어는 현재 MVP 범위에서 제외한다. `.dwg`, `.dxf`, `.step`, `.stp`, `.iges`, `.igs`, `.hwp`, `.hwpx`는 원본 첨부, 문서 메타데이터, FieldComment, 열람 시작/종료/다운로드 차단 로그만 기준으로 한다.

## 검증

WPF 스모크 테스트는 다음을 검증한다.

- TXT/PDF/XLSX/이미지 각각에 정상, 비정상, 한글 파일명, 공백/괄호 파일명, 긴 경로, 큰 파일 샘플 기준이 정의되어 있다.
- 긴 TXT, 손상 PDF, 암호 PDF, 긴 경로 TXT, 다중 시트·수식·병합 XLSX, 회전·투명도·고해상도 이미지, 손상 이미지, 미지원 CAD/HWP의 합성 예외 샘플 목록이 정의되어 있다.
- 미지원 또는 손상 파일은 앱을 종료하지 않고 한글 안내와 `document.preview_failed` 이력을 남기는지 확인한다.
- TXT/PDF/XLSX/이미지 대표 샘플을 등록한다.
- 각 유형별 열람 시작, 사용자의 열람 종료, 다운로드 차단 로그가 공통 SQLite에 남는다.
- 스모크 테스트 출력에 `Preview audit smoke` 줄로 파일 유형, 샘플 파일 경로, 로그 ID가 남는다.
- 테스트 산출물은 로컬에 보존하되 SQLite를 포함한 DB와 입력·출력 파일은 Git 추적 대상에 포함하지 않는다.
- 권한 없는 role은 기존 다운로드 차단 안내와 이력을 유지하고, 허용 role의 controlled copy는 서버 문서/버전 매핑·1회성·SHA-256 검증을 통과해야 한다.
- WebView2 Runtime 누락 안내에는 PDF 파일 유형, 뷰어 구성요소 실패 범주, 보존 상태와 Windows 설치 담당자의 다음 행동이 모두 포함되어야 한다.
- 승인된 실제 익명 현장 표본을 실행하면 합성 결과와 분리된 run·보고서로 보존하고 결과를 합산하지 않는다.

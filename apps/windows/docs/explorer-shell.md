# 탐색기형 메인 화면

이 문서는 2026-08-01 현재 WPF 메인 화면과 연결된 서비스 기준이다.

## 목적

Windows WPF 메인 화면은 현장/관리자가 폴더 트리에서 문서를 찾고, 문서를 등록하고, 현재 문서의 상태와 버전을 확인하는 작업 화면이다.

## 화면 구성

- 상단: 로그인 사용자와 계정·알림·현장 운영·AI·문서 운영 메뉴
- 역할 우선 동선: 로그인 역할의 첫 업무 3개와 바로 가기, 권한 안내
- 좌측: 문서 폴더 트리
- 우측 상단: 문서 검색, 등록 태그, 문서 상태 필터, 선택 문서 열기
- 우측 중앙: 문서 목록
- 하단: 현재 작업 상태와 서버 동기화 완료 여부·보존 여부·다음 조치

## 역할별 로그인 첫 업무

| 역할 | 1순위 | 2순위 | 3순위 |
| --- | --- | --- | --- |
| 관리자·문서 관리자·부서 관리자 | 코멘트 검토 | 보고서 근거 선정 | 동기화·충돌 확인 |
| 반장 | 인수인계 확인 | 문서 찾기·열람 | 작업판 |
| 조장 | 작업 전 문서 확인 | 인수인계 확인 | 채널 알림 |
| 작업자·열람자 | 문서 찾기·열람 | 인수인계 확인 | 알림 확인 |

역할 우선 동선의 세 버튼은 기존 창과 권한 검사를 그대로 호출한다. 빠른 버튼이 권한 검사를 우회하는 별도 저장·변경 경로가 되어서는 안 된다.

권한이 없는 메뉴는 위치를 숨기지 않고 비활성 상태로 표시한다. 비활성 항목의 설명과 역할 안내 영역에는 필요한 역할과 `현장 관리자에게 로그인 ID와 필요한 업무를 전달`하는 문의 방법을 함께 표시한다. 버튼 상태만 보고 권한을 추측하게 하지 않는다.

## 문서 검색과 필터

- 검색은 파일명, 제목, 태그, 사용자, 최근 코멘트를 대상으로 한다.
- 검색어를 입력하고 Enter를 누르면 선택 문서 또는 첫 검색 결과를 연다. `선택 문서 열기` 버튼과 기존 목록 더블클릭도 같은 문서 보기 경로를 사용한다.
- 상태 필터는 전체, 작업중, 검토중, 공개, 보관을 제공한다.
- 검색어와 상태 필터는 폴더 이동, 목록 갱신, 문서 보기 뒤에도 유지한다. 결과 수는 `전체 N개 중 M개 표시`로 안내한다.
- `등록 태그` 입력은 새 문서 등록용이며 문서 검색 필터와 구분한다.

## 기본 폴더

로컬 SQLite 초기화 시 루트 아래 다음 시스템 폴더를 만든다.

- 문서
- 인수인계
- 작업순서
- 사진

`문서` 아래에는 다음 분류 폴더를 만든다.

- 도면
- 작업표준서
- 점검표
- 품질검사
- 안전수칙
- 보전작업
- 일반문서

시스템 폴더는 삭제 대상이 아니다.

## 문서 등록 규칙

- 파일 업로드와 Drag & Drop은 파일을 `Files/Uploads/yyyy-MM-dd/` 아래 복사한다.
- 새 문서는 `WORKING` 상태와 버전 `v1`로 저장한다.
- `문서` 폴더에 등록하면 파일명/문서 유형 기반으로 하위 분류 폴더에 자동 배치한다.
- `인수인계`와 `사진` 폴더는 오늘 날짜 `yyyy-MM-dd` 하위 폴더에 배치한다.
- `작업순서` 폴더는 별도 자동 분류 없이 선택 폴더에 문서를 등록한다. 작업순서 보드/항목 관리는 상단 `작업순서` 화면에서 수행한다.
- 태그 입력값과 폴더/문서 유형/확장자 기반 태그를 함께 저장한다.

## 문서 보기

문서 목록을 더블클릭하면 문서 보기 창을 연다. 현재 미리보기는 텍스트, PDF, Excel 첫 시트, 이미지 파일을 지원한다. 문서 보기 창은 열람 시작/종료 로그를 남기며 사용자가 직접 닫을 때까지 유지된다. 일반 저장은 차단하며, 다운로드 허용 role은 서버에 매핑된 현재 공개 버전에 한해 1회성 controlled copy 티켓으로 저장하고 SHA-256을 검증한다.

## FieldComment

문서 보기 창에서 작성한 새 코멘트는 `field_comments`에 저장되며 문서 버전을 증가시키지 않는다. 첨부 사진/파일은 `field_comment_attachments`와 로컬 `Files/FieldCommentAttachments/` 아래 저장된다. 관리자 검토 화면은 원천 내용을 읽기 전용으로 표시하고 담당자·기한·정리·분석·상태·전이 사유를 별도 저장하며 상세 필터·일괄 변경·품질 작업함을 제공한다. 화면 상단은 서버의 `review-dashboard`와 AI 준비도를 함께 조회해 미검토·상충·안전/품질 위험·보고서 미연결·담당자 없음 수를 보여준다. 실제 익명 현장 자료의 부족 범주·유형은 합성·시험 회귀와 분리하며 서버 조회에 실패하면 로컬 수치로 대신하지 않는다.

메인 화면의 역할 우선 동선은 다음 연결을 제공한다.

- 문서 찾기 → 검색 후 Enter로 열람 → 문서 보기에서 FieldComment 입력
- 인수인계 확인 → 채널함에서 수신 상태 확인 → 같은 화면에서 후속 FieldComment 생성
- 코멘트 검토 → 관리자 검토 반영 → 빠른 업무 `보고서 근거 선정`에서 선정된 FieldComment를 보고서 근거로 확인

## 서버 연동

서버 URL과 Bearer token이 있으면 문서 최초 등록, 문서 버전, 문서 공개, 문서 상태, 문서 태그, FieldComment, FieldComment 검토, 첨부, 접근 로그, 보고서 서버 저장을 서버로 전송한다. 실패하면 로컬 저장은 유지되고 `server_sync_queue`에 실패 사유가 남는다. 재시도는 문서 등록, 버전, 공개, 상태, 태그, FieldComment, 검토, 첨부, 접근 로그, 보고서 순서의 선행 조건을 따른다.

메인 화면 하단은 색상과 별개로 동기화 상태를 문장으로 표시한다.

- 미완료: 대기, 실패·충돌, 그중 보류 건수
- 보존 여부: 로컬 데이터와 원본 파일을 삭제하지 않음
- 다음 조치: `이력 > 동기화 큐`에서 사유와 조치를 확인
- 서버 미연결: 로컬 기록은 보존되며 서버 주소 확인과 재로그인이 필요함
- 완료: 서버 확인 대기·실패·충돌이 없음을 명시

AI 근거 후보 운영 점검 화면은 서버 URL과 로그인 토큰이 있을 때 `/api/v1/ai-search/candidates/rebuild`, `/api/v1/ai-search/quality`, `/api/v1/ai-search/candidates`, `/api/v1/ai-search/readiness`를 호출한다. 이 화면은 외부 AI 호출을 하지 않고 서버 DB의 후보 수, 제외 사유, FieldComment 검토 준비도, 원천 추적값과 고객·현장·DB scope별 실제 현장/스모크 준비도를 확인하는 운영 화면이다. ground-truth 사례·원천 구성, 독립 2인 사례 승인, dataset version 전이와 회귀 실행·비교는 별도 `AI 정답셋` 화면이 담당한다. `system-admin` 전용 `AI 운영` 화면은 전송 승인·프롬프트·정책·감사·보존 제어를 담당하며 실제 외부 AI 질의 실행 화면은 제공하지 않는다.

채널함, 채널 관리, 인수인계 확인 현황 화면은 서버 URL과 로그인 토큰이 있을 때 FastAPI 채널/인수인계 API를 직접 호출한다. 채널함은 내 채널, 알림, 인수인계를 조회하고 읽음/수신 확인과 후속 FieldComment 생성을 수행한다. 채널 관리와 인수인계 확인 현황은 문서 등록 권한이 있는 관리자/반장/조장 계열 role에서 활성화된다.

controlled copy도 서버 직접 호출 기능이다. 로컬 문서/버전에 서버 ID 매핑이 없거나 서버 URL·로그인 토큰이 없으면 저장을 시작하지 않으며, 실패 내용을 동기화 큐로 재시도하지 않는다.

## MainWindow 책임 경계

`MainWindow`는 WPF 이벤트 연결을 위해 partial class를 유지하되 책임별 파일을 분리한다.

- `MainWindow.xaml.cs`: 생성, 서버 클라이언트 연결, 수명주기
- `MainWindow.Navigation.cs`: 폴더 탐색, 문서 검색·필터, 선택 유지
- `MainWindow.DocumentCommands.cs`: 등록, 업로드, 상태·공개, 문서 열기
- `MainWindow.WindowCommands.cs`: 알림·채널·작업판·검토·보고서 등 보조 창 열기
- `MainWindow.StatusDisplay.cs`: 역할 우선 동선, 권한 안내, 알림 확인, 동기화 상태

각 파일은 1,000줄 이하를 유지한다. 새 메인 화면 기능은 주된 책임 파일에 추가하고, 기존 공개 창 생성자와 서비스 호출 계약을 임의로 바꾸지 않는다.

# Apps

FlowNote 클라이언트를 보관하는 영역이다.

아래 역할 구분은 2026-07-21 현재 실제 Windows·Android 코드 기준이다.

클라이언트 UI는 승인된 설치형 네이티브 앱을 기본으로 한다. Windows WPF는 관리자/현장 PC용이고, Android는 현장 태블릿 또는 러기드 단말용이다. 로컬 제어가 필요한 기능은 각 클라이언트 앱에서 직접 처리한다.

## 역할

- `windows/`: 활성 Windows WPF 클라이언트
- `android/`: Android 현장 단말 클라이언트. Java/Android 네이티브 View 기반 최소 앱과 단위 테스트를 포함한다.

## 설계 원칙

- UI/UX 변경 대응은 Windows WPF 클라이언트의 실제 운영 화면을 기준으로 처리한다.
- Windows와 Android는 역할을 분리한다. Windows는 관리, 파일 감시, 문서 운영, 문서 파일 미리보기, FieldComment 검토·품질 작업함, 보고서 정리, 채널 수신함, 채널 관리, 인수인계 확인 현황, 승인 단말 운영과 `system-admin` 전용 외부 AI 운영 제어 중심이다. WPF의 AI 운영 범위는 일괄 만료까지이며 서버의 단일 AI 질의 만료·legal hold API에는 아직 연결되지 않는다. Android 현재 코드는 공개 문서 목록·상세, PDF/이미지/TXT 앱 내부 보안 열람, FieldComment, 사진 기록, 신호등식 기록, 인수인계 확인, 채널 알림을 담당하며 인수인계 작성은 구현되어 있지 않다.
- 서버 원본 문서를 사용자 단말기에 무차별 동기화하는 구조를 피한다. WPF는 사용자가 등록하거나 열람 흐름에서 필요한 로컬 복사본과 FieldComment 첨부만 `Files/` 아래 관리한다.
- Android는 개인 휴대폰 기본 배포가 아니라 승인된 현장용 단말 배포를 기준으로 한다.
- 파일 감시, 로컬 파일 선택, 알림 같은 기능은 앱 네이티브 기능으로 제공한다.

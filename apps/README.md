# Apps

FlowNote 클라이언트를 보관하는 영역이다.

아래 역할 구분은 2026-08-06 현재 실제 Windows·Android 코드 기준이다.

클라이언트 UI는 승인된 설치형 네이티브 앱을 기본으로 한다. Windows WPF는 관리자/현장 PC용이고, Android는 현장 태블릿 또는 러기드 단말용이다. 로컬 제어가 필요한 기능은 각 클라이언트 앱에서 직접 처리한다.

## 역할

- `windows/`: 활성 Windows WPF 클라이언트
- `android/`: Android 현장 단말 클라이언트. Java/Android 네이티브 View 기반 최소 앱과 단위 테스트를 포함한다.

## 설계 원칙

- UI/UX 변경 대응은 Windows WPF 클라이언트의 실제 운영 화면을 기준으로 처리한다.
- Windows와 Android는 역할을 분리한다. Windows는 관리, 파일 감시, 문서 운영·미리보기, 문서 검토·공개 승인, FieldComment 검토·품질 작업함·원천 추적, 단계형 보고서 정리와 확정본 정정, 통합 변경 이력·운영 준비도, 작업순서 후보 전달, 채널 수신함·관리, 인수인계 확인 현황, 승인 단말 운영과 `system-admin` 전용 외부 AI 운영 제어를 담당한다. WPF의 AI 운영 화면은 민감정보 정책 수명주기, 차단 구분과 실제 외부 전송 여부, 일괄 만료, 고객·현장 질의 상세, 단일 즉시 만료, legal hold 설정·해제와 감사 재조회까지 현재 서버 API에 연결되어 있다. Android는 공개 문서 목록·상세, PDF/이미지/TXT 앱 내부 보안 열람, 오늘의 작업순서와 공개 문서 연결, 작업순서 원천의 FieldComment·사진·인수인계, 신호등식 기록, 인수인계 확인·보류와 같은 원천의 후속 FieldComment, 채널 알림을 담당한다. 신규 인수인계와 받은 인수인계의 확인·보류·후속 FieldComment는 전송 전에 암호화 outbox에 보존하고 같은 멱등키로 재전송한다.
- 서버 원본 문서를 사용자 단말기에 무차별 동기화하는 구조를 피한다. WPF는 사용자가 등록하거나 열람 흐름에서 필요한 로컬 복사본과 FieldComment 첨부만 `Files/` 아래 관리한다.
- Android는 개인 휴대폰 기본 배포가 아니라 승인된 현장용 단말 배포를 기준으로 한다.
- 파일 감시, 로컬 파일 선택, 알림 같은 기능은 앱 네이티브 기능으로 제공한다.
